# KinetCamera 拍照痛点清单 —— 每条对应已落地功能或明确砍掉理由

> 对标来源:HN 计算摄影长文(278分《limits of computational photography》)、
> 苹果"婚纱照"事件(504分)、Reddit r/photography 高频吐槽、Adobe Project Indigo 方向。
> 原则:**每条痛点要么有已落地的功能+实测证据,要么写明砍掉理由。光喊超越没意义。**

## 一、已解决(功能落地 + 实测证据)

| # | 痛点 | 用户原声场景 | 已落地解法 | 实测证据 |
|---|------|------------|-----------|---------|
| 1 | **快门慢半拍,精彩瞬间拍完才想到** | 孩子表情/宠物跳跃,按下快门画面已经过去 | 回溯快门:60帧环形缓冲(2s)持续在录,⌘R/POST /retro 从过去捞帧,AIAnalyzer 清晰度+曝光综合分选最佳帧 | 实测扫描60帧取#0落盘 1280×720 PNG + 报告JSON |

## 二、明确砍掉(写清理由,不做半吊子)

| # | 功能 | 砍掉理由 |
|---|------|---------|
| A | **计算HDR合成** | 依赖 RAW 级多帧像素对齐,macOS 公开 API 只有 IOSurface 级帧访问,对齐精度做不到 iPhone Deep Fusion 水准;做出来只会重蹈 HN 长文控诉的"先验涂抹"覆辙。等 AVFoundation 开放 bracketed RAW 再补。**现状用夜景时域平均+增益替代,不宣称HDR** |
| B | **人像光斑虚化** | 无 LiDAR/双摄深度图的 Mac 上做单目虚化=人像边缘必然撕裂(HN婚纱照事件同款翻车)。拒绝交付垃圾边缘。**保留手动光圈模拟(暗角+背景压暗滑杆)作为诚实替代** |
| 5× | **AI消除/生成式填补** | 同 A:端侧生成式填补必然涂抹文字/结构,违背"细节不可撒谎"底线。要消除去专业工具,相机不做魔术 |
