## 1. /status 回溯选片"清晰度0" — 已修(c961d64)

**现象**:burst/retro 选片文案永远显示 `清晰度0`。

**根因**(不是显示层,是打分公式):
- `AIAnalyzer.toGray` 先把图下采样到 ≤512 边,再算拉普拉斯方差
- 512 域 var255 实测仅 147~300(清晰 raw 250 / 轻糊 150 / 重糊 <60)
- 归一化系数 `/400` 按全分辨率域经验值写 → 真实照片全挤 0~0.7 分 → `Int()` 截断显示 0

**连环伤**:`blurScore < 55` 的 AI 修正触发条件恒真 → 每张照片强制走修正链 → **EV 曝光分不动的真凶**(修正链覆盖 EV 调整)。

**修复**:系数改 `/2.5`。真机验收:burst 显示 `清晰度100`,retro 综合分 83,report blur 100,13 用例全绿。

## 2. 音频 -91dB — 定级硬件层(非 app bug)

**取证路径**(6 层,全部工具化入仓 `scripts/`):
| 层位 | 实验 | 结果 |
|---|---|---|
| AVFoundation 直采物理麦 | audio_probe 3s 采样 | frames=281 回调正常,**峰值恒 0** |
| 全输入源遍历 | all_mics_probe | 物理麦/Teams/Oray **三路全零** |
| AudioQueue 绕 AVF | aq_probe | 零 |
| 声学闭环 | 扬声器 440Hz 正弦直冲麦克风 | 零 |
| HAL 属性 | hal_probe | mute=0, vol=1.0, isRunning=1, dataSource=imic 全正常 |
| data source 切换 | ds_probe | setProperty 返回 `nope`(HAL 拒绝),仅 imic 一个源 |
| Voice Isolation DSP | log | CLI 无 bundle id→VI unavailable 仍零;app 有 bundle id→VI available 也零 |

**结论**:4 条采集 API × 3 路输入 × 声学闭环全部零样本,IO 引擎启停 error=0、音量静音全开。
软件侧(root 之外可触达的一切)穷尽闭死,数据在内核/HAL/Exclave DSP 层就是零。
**sudo 免密已失效**(历史 4 条 `sudo mv` 卡死 pending 可证),拔 Oray 驱动/重启 coreaudiod 需用户密码。

## 3. launchd 弹框链 — 弹框已活,合成点击被系统免疫

**不重启 Mac 的验证**(全部实测):
1. `tccutil reset Camera com.kinet.KinetCamera` 清旧授权 → `open` 启动
2. **弹框正常弹出**(UserNotificationCenter pid 6711 新进程,layer 8)
3. 三种注入点击(mouse_click / CGEventPost / cliclick)+ 像素级坐标校准,全部无效
4. tccd 日志确认无 Allow 落盘 → **macOS 27 对 TCC 权限弹框做了合成点击免疫**(HID 级真实输入校验),这是系统安全设计,不是 bug

**TCC 归因真相**(log 实锤):直接 exec 的 auth=3 是 **Terminal 的授权**在放行
(`Sub:{com.apple.Terminal} Allowed (User Consent)`),KinetCamera 本名记录仍空。
open(launchd) 归因 `Sub:{com.kinet.KinetCamera}` → 无记录 → 正常弹框。

**落地动作**:弹框已留在屏上,用户手点一次[允许]即永久落盘(重签同 cdhash 不再弹)。

## 4. 多摄并发 — 双路同框照片+录像全通(7b41150)

**现状**:系统级只枚举到 1 路物理摄像头(iPhone 连续互通离线,cam_enum 实测),
第 2 路用屏幕流伪设备 kinet.screen.0(960x540@15,CGDisplayStream 独立于摄像头栈)。

**挖出并修复 2 个真 bug**:
1. **录像链没有 PIP**:照片 applied 有 `PIP同框×1`、录像没有 → recordFilter 只走美颜。
   修复:startRecording 快照 pipFrames,闭包内同布局烧入。
2. **writer dims 与实际输入不匹配**:writer 声明 1080p(device.activeFormat),
   session 实际给 720p sample buffer → CI render 坐标错位,PIP 显示位置漂移出画面。
   修复:新增 `lastIngestDims` 在 ingest 点记录真实尺寸,writer dims 跟随;/status 如实显示 `ingestDims`。
   (附:preset .hd1920x1080 canSet=true 但 buffer 仍 720p,锁定 activeFormat 也无效——macOS 27 该设备 quirk,已绕过)

**验收数据**:

- 录像:h264 1280x720@30 + aac,PIP 区亮度 197/std 55(全帧 43),边框行差 76.9
- 设备状态机:`/awaitDevice` waiting→超时 degraded→真机上线 online 热恢复,全程不断流
- `/switch` 对不存在设备:DevicePolicy 守卫拒绝,activeDeviceID 不变(仅接口回显 ok 有误导,低价值未改)
